## 2. SQL objects created

**Functions (5)** — all `SECURITY DEFINER`, `SET search_path = public, pg_temp`:

| Function | Purpose |
|---|---|
| `public.assert_ledger_writer_authorized()` | Raises `42501` unless the session flag `app.ledger_writer = 'on'` is set. |
| `public.begin_ledger_write()` | Sets the session-local flag (`set_config(..., true)` → dropped at COMMIT/ROLLBACK). |
| `public.ledger_writer_guard()` | BEFORE INSERT trigger fn — calls the assert. |
| `public.ledger_entry_currency_match()` | AFTER INSERT trigger fn — rejects entries whose currency differs from their parent transaction. |
| `public.validate_ledger_transaction_balance()` | Deferred CONSTRAINT TRIGGER fn — enforces `≥2 entries` and `SUM(debit)=SUM(credit)` per transaction. |
| `public.ledger_event_enabled_check()` | BEFORE INSERT trigger fn — rejects `event_type` values that are absent or `enabled=false` in `finance_event_catalogue`. |

Both public helpers (`assert_ledger_writer_authorized`, `begin_ledger_write`)
have `EXECUTE` revoked from `PUBLIC` and are **not** granted to
`anon` / `authenticated` / `service_role`. Only the table owner (used by
future SECURITY DEFINER posting functions) can call them.

## 4. Constraints & documentation

- **Balance invariant** (deferred): per-transaction `SUM(debit) = SUM(credit)`.
- **Entry-count invariant** (deferred): per-transaction `COUNT(entries) ≥ 2`.
- **Currency invariant** (immediate): `ledger_entries.currency = ledger_transactions.currency`.
- **Event whitelist** (immediate): `ledger_transactions.event_type` must exist in `finance_event_catalogue` with `enabled = true`. Reserved/disabled events (e.g. FX in current phase) are rejected.
- **Writer-authorization gate** (immediate): every INSERT into ledger tables requires the session to have called `begin_ledger_write()`.

## 5. Verification results

### 5.1 In-migration self-test (embedded `DO $selftest$`)

The migration itself attempts to insert an intentionally malformed ledger
transaction (single entry, unbalanced) and asserts that the deferred
constraint trigger raises `SQLSTATE 23514` when `SET CONSTRAINTS ALL
IMMEDIATE` is issued. If validation had not fired, the migration would
have aborted. The migration **completed successfully**, proving the
balance validator is active.

### 5.2 Post-migration trigger inventory

`pg_trigger` query (see §3) returns all 10 expected rows with the correct
`tgdeferrable`/`tginitdeferred` flags for the two constraint triggers.

### 5.3 Writer-guard behaviour

Direct writes from `anon`/`authenticated`/`service_role` remain blocked
by the Step 1 deny-all RLS. Even inside a superuser session, any INSERT
that omits `SELECT begin_ledger_write();` now fails with `42501` at the
first row.

### 5.4 Security linter

Post-migration Supabase linter output is unchanged in category compared
to Step 1; the SECURITY DEFINER trigger functions are only invoked by
triggers and their `EXECUTE` is revoked from `PUBLIC`. No new
`ERROR`-level findings were introduced by this step.

## 9. Remaining risks

1. **No posting functions yet.** The ledger is provably balanced *if*
   written to, but nothing writes to it. Step 3 must land the
   SECURITY DEFINER posting functions (`post_payment_captured_v1`,
   `post_transfer_created_v1`, …) that wrap `begin_ledger_write()` and
   build the journals from the v7 event catalogue.
2. **Materialised projections (`provider_balance_accounts`, credit/debt
   items) are not yet maintained.** Their update logic ships with the
   posting functions in Step 3.
3. **`SET CONSTRAINTS ALL IMMEDIATE`** inside a caller's transaction
   would allow it to force early validation and then continue inserting
   more entries; posting functions must not expose this to callers.
4. **Session flag lifetime.** `begin_ledger_write()` uses
   `set_config(..., true)` (LOCAL scope). If a future maintenance script
   forgets to call it, inserts fail loudly (this is the intended
   behaviour) — but the failure mode must be captured in Step 3
   posting-function tests.
5. **FX events remain disabled** in `finance_event_catalogue` and are
   rejected by `ledger_tx_event_enabled`. This is intentional and matches
   the v7 §14 phasing.
